# Agent 与评测：怎样判断结果可用

## 工作流设计

1. 教练输入训练目标和条件。人数、时长等必要信息不明确时，系统先澄清；本次明确输入或已确认的球队背景才能作为硬约束。
2. 稳定的训练设计原则放入主题参考，具体练习和完整课次由正式案例库提供。候选材料未准入前不参与检索；案例区分原文事实和整理判断。
3. 本地检索先召回候选，再让模型在可提供的案例范围内判断适配性；程序检查证据指向、人数和时长等确定条件。保存、取消和恢复由程序管理，旧结果不能覆盖新版。

## 已有证据与待验证事项

| 证据 | 说明 |
| --- | --- |
| 案例资产 | 共 9 个训练主题的中英双语设计参考；正式案例库 25 个案例。入库与结构检查不等于独立教练评审。 |
| 本地原型 | 支持需求澄清、正式案例检索、课次生成与修改、结构检查、保存及历史恢复。历史回归覆盖正常与失败路径。 |
| 真实调用 | 一次真实联调生成并保存 U12、12 人、60 分钟训练课。该结果不能代表对同一需求的稳定复现，亦未经过实际训练验证。 |
| 检索拆评 | 将检索单独评测，固定输入、预先记录逐项证据判据，设计重复对照。一轮响应虽通过格式处理，语义复核仍发现证据借用相邻活动和判断与来源不符。新版复测材料已准备，未取得新版真实评测结论。 |
| 展示版 | `demo/` 是用虚构数据和预设交互展示产品流程的静态版本，与上述本地 Agent 和真实模型联调分离。 |

公开仓库提供[案例 Schema](../schemas/case-v0.2.schema.json)和[检索 Schema](../schemas/search-training-examples-v0.2.schema.json)，用于展示如何约束数据结构。原始资料、真实调用载荷、评测标准答案和服务配置未纳入展示范围。
